# План реализации MVP SEIVA

## 1. Цель
Сделать рабочий веб-инструмент для менеджера MICE-агентства: заполнить бриф, получить программу по дням от AI, отредактировать, собрать презентацию и экспортировать в PDF.

## 2. Зафиксированный scope MVP

### 2.1. Обязательно в первом релизе
1. Форма брифа с обязательной валидацией.
2. Поддержка нескольких стран + опция предложить альтернативу.
3. Генерация программы по дням в структурированном формате.
4. Редактор программы: правка текста, перестановка блоков и дней.
5. Замена каждой картинки вручную.
6. Автосохранение в черновик.
7. Формирование презентации из утвержденного документа.
8. Экспорт в PDF.

### 2.2. Вне MVP
- импорт PDF/DOCX/XLSX;
- роли и личные кабинеты;
- многопользовательская совместная работа;
- поставщики, цены, интеграции DMC;
- PPTX-экспорт и сложные шаблоны;
- авто-переписывание контента после каждого ручного изменения.

## 3. Обязательные поля брифа
1. Количество участников.
2. Сфера компании.
3. Тип мероприятия: инсентив, конференция, VIP, круглый стол и другие варианты.
4. Страны (множественный выбор + добавление вручную).
5. Галочка предложить альтернативу стране.
6. Примерный возраст участников.
7. Соотношение мужчин и женщин (формат вида 70/30).
8. Интерес к спорту/экстриму.
9. Цель поездки.
10. Ограничения/что нельзя.

## 4. Основной пользовательский поток
1. Менеджер заполняет бриф.
2. Система генерирует предварительную программу по дням.
3. Менеджер правит программу и содержание блоков.
4. Система формирует финальный текст презентационного уровня.
5. Менеджер меняет изображения при необходимости.
6. Формируется презентация.
7. Результат сохраняется в черновик и экспортируется в PDF.

## 5. Техническая схема (для реализации)

### 5.1. Frontend
1. `brief` страница формы.
2. `generate` экран статуса генерации.
3. `programme-editor` экран редактирования по дням.
4. `presentation` экран предпросмотра.
5. `drafts` список черновиков.

### 5.2. Backend API
1. `POST /api/briefs` - сохранить бриф.
2. `POST /api/programmes/generate` - сгенерировать программу через AI.
3. `PATCH /api/programmes/{id}` - обновить программу после ручной правки.
4. `POST /api/programmes/{id}/presentation` - собрать презентацию.
5. `POST /api/programmes/{id}/export-pdf` - экспорт PDF.
6. `POST /api/assets/upload` - загрузка и замена изображений.

### 5.3. Данные (минимум)
1. `briefs`.
2. `programmes`.
3. `programme_days`.
4. `programme_blocks`.
5. `presentations`.
6. `drafts`.
7. `assets`.

### 5.4. AI-слой
1. Ключ AI только на сервере.
2. На вход AI отправляется только структурированный бриф.
3. Ответ принимается только в JSON по схеме.
4. При невалидном JSON - один автоповтор.
5. Если повтор неудачен - честная ошибка, без фейкового контента.

## 6. План разработки по очереди

### Этап 1. Каркас
1. Инициализация frontend + backend.
2. Подключение базы данных.
3. Базовые модели `brief` и `programme`.

### Этап 2. Бриф
1. Экран формы.
2. Валидация обязательных полей.
3. Сохранение брифа.

### Этап 3. Генерация
1. Подключение AI-провайдера (первый кандидат: GigaChat).
2. Эндпоинт генерации.
3. Проверка JSON-схемы.
4. Отображение программы по дням.

### Этап 4. Редактор
1. Правка текста.
2. Перестановка дней и блоков.
3. Загрузка и замена изображений.
4. Автосохранение черновика.

### Этап 5. Презентация и PDF
1. Сборка презентации из утвержденного контента.
2. Предпросмотр.
3. Экспорт в PDF.

### Этап 6. Проверка качества
1. Прогон полного сценария на реальном брифе.
2. Проверка пограничных случаев и ошибок.
3. Фикс критичных багов.

## 7. Что делаем прямо сейчас
1. Зафиксировать технологический стек.
2. Создать структуру проекта.
3. Реализовать форму брифа + сохранение.
4. Подключить временную генерацию (stub) и вывести программу на экран.

После этого MVP уже будет "живым", и можно безопасно подключать реальный AI и редактор.

## 8. Рекомендуемый стек (чтобы не тормозить старт)
1. Frontend: Next.js (App Router) + TypeScript + Tailwind.
2. Backend: API Routes в Next.js на первом этапе.
3. База: PostgreSQL + Prisma ORM.
4. Хранение файлов: S3-совместимое хранилище (или локально на этапе dev).
5. Валидация: Zod для схем брифа и AI-ответа.
6. Генерация PDF: Playwright/Puppeteer по HTML-шаблону презентации.
7. AI: GigaChat как первый провайдер, через серверный адаптер.

## 9. Стартовая структура проекта
1. `apps/web` - интерфейс и API.
2. `packages/ui` - переиспользуемые компоненты.
3. `packages/core` - типы, схемы, бизнес-логика.
4. `packages/ai` - адаптер провайдера AI и промпты.
5. `packages/db` - Prisma schema, миграции, доступ к БД.
