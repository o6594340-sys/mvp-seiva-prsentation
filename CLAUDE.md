# SEIVA MVP — контекст проекта

> Этот файл — источник истины по проекту вместо повторного чтения `brief.md` и `plan.md` в начале каждой сессии.
> Правило поддержки: в конце сессии, где были значимые изменения (новая фича, смена решения, смена стека, готовый этап), обновляй раздел «10. Текущий статус реализации» и, если изменился сам план — соответствующие разделы выше. Не жди явной просьбы — это часть обычной работы.

## 1. Что это за проект
Веб-инструмент для менеджера MICE-агентства (корпоративные поездки, инсентивы, конференции):
заполнить бриф → получить программу по дням от AI → отредактировать → собрать презентацию → экспортировать в PDF.

Полные первоисточники (уже учтены здесь, перечитывать не нужно): `brief.md`, `brief.docx`, `plan.md`.

## 2. Зафиксированный scope MVP

### Обязательно в первом релизе
1. Форма брифа с обязательной валидацией.
2. Поддержка нескольких стран + опция «предложить альтернативу».
3. Генерация программы по дням в структурированном формате.
4. Редактор программы: правка текста, перестановка блоков и дней.
5. Замена каждой картинки вручную.
6. Автосохранение в черновик.
7. Формирование презентации из утвержденного документа.
8. Экспорт в PDF.

### Вне MVP (сознательно не делаем)
- импорт PDF/DOCX/XLSX;
- роли и личные кабинеты;
- многопользовательская совместная работа;
- поставщики, цены, интеграции DMC;
- PPTX-экспорт и сложные шаблоны;
- авто-переписывание контента после каждого ручного изменения.

## 3. Обязательные поля брифа
1. Количество участников.
2. Сфера компании.
3. Тип мероприятия: инсентив, конференция, VIP, круглый стол и др.
4. Страны (множественный выбор + добавление вручную).
5. Галочка «предложить альтернативу стране».
6. Примерный возраст участников.
7. Соотношение мужчин и женщин (формат «70/30»).
8. Интерес к спорту/экстриму.
9. Цель поездки.
10. Ограничения/что нельзя.
11. Количество дней поездки (обязательно — точную дату не все знают, а число дней знают всегда).
12. Дата заезда (необязательно; если задана — дни в программе подписываются календарными датами, если нет — просто «День 1», «День 2» и т.д.).
13. Интенсивность программы: Умеренная / Активная / Насыщенная (с утра до вечера) — добавлено по фидбэку 2026-08-10 взамен использования поля «интерес к спорту/экстриму» для темпа программы; это два разных измерения (спорт/экстрим — про тип активностей, интенсивность — про плотность расписания).

## 4. Пользовательский поток
1. Менеджер заполняет бриф.
2. Система генерирует предварительную программу по дням.
3. Менеджер правит программу и содержание блоков.
4. Система формирует финальный текст презентационного уровня.
5. Менеджер меняет изображения при необходимости.
6. Формируется презентация.
7. Результат сохраняется в черновик и экспортируется в PDF.

## 5. Целевая техническая схема (по плану)

**API (целевой, из плана):**
- `POST /api/briefs` — сохранить бриф.
- `POST /api/programmes/generate` — сгенерировать программу через AI.
- `PATCH /api/programmes/{id}` — обновить программу после ручной правки.
- `POST /api/programmes/{id}/presentation` — собрать презентацию.
- `POST /api/programmes/{id}/export-pdf` — экспорт PDF.
- `POST /api/assets/upload` — загрузка и замена изображений.

**Данные (минимум, из плана):** briefs, programmes, programme_days, programme_blocks, presentations, drafts, assets.

**AI-слой (правила):**
1. Ключ AI только на сервере.
2. На вход AI — только структурированный бриф.
3. Ответ принимается только в JSON по схеме.
4. При невалидном JSON — один автоповтор.
5. Если повтор неудачен — честная ошибка, без фейкового контента.

**Рекомендованный стек по плану:** Next.js (App Router) + TypeScript + Tailwind, API Routes, PostgreSQL + Prisma, S3-совместимое хранилище файлов, Zod-валидация, Playwright/Puppeteer для PDF, GigaChat как первый AI-провайдер.

**Целевая структура (по плану, ещё не создана):** `apps/web`, `packages/ui`, `packages/core`, `packages/ai`, `packages/db`.

## 6. Фактический стек (что реально стоит сейчас)
- Next.js 16.3.0 (App Router), React 19.2.8, TypeScript, Tailwind CSS 4.
- Хранилище данных: **плоские JSON-файлы** `apps/web/data/briefs.json` и `apps/web/data/programmes.json` — PostgreSQL/Prisma ещё не подключены.
- Валидация: ручная (написана вручную в route-хендлерах), Zod не подключен.
- AI-провайдер не подключен — программа генерируется **стабом** (см. ниже).
- Монорепо-разделение на `packages/*` пока не сделано — весь код в `apps/web`.

## 7. Фактическая структура проекта
```
apps/web/
  app/
    page.tsx                    — форма брифа (главная страница)
    drafts/page.tsx             — список сохранённых брифов
    programme/[id]/page.tsx     — редактор программы по дням
    api/briefs/route.ts         — POST/GET брифов + стаб-генерация программы
    api/programmes/[id]/route.ts — GET/PATCH программы
  data/briefs.json, data/programmes.json — файловое "хранилище" на этапе прототипа
  CLAUDE.md                     — авто-файл Next.js (@AGENTS.md), НЕ трогать/не путать с этим файлом
```

## 8. Реализовано сейчас
- Форма брифа (`app/page.tsx`) со всеми полями из раздела 3, включая количество дней (обязательно), дату заезда (опционально) и интенсивность программы; клиентская валидация обязательных полей, добавление/удаление стран, форматирование соотношения м/ж как `NN/NN`.
- `POST /api/briefs` — валидирует payload, сохраняет бриф в `data/briefs.json`, тут же генерирует программу через `buildStubProgramme()` (детерминированный стаб, генерирует ровно `durationDays` дней: день заезда → N ключевых дней → день отъезда, либо один комбинированный день при duration=1; интенсивность меняет плотность блоков — «Насыщенная» добавляет доп. блок в день, «Умеренная» добавляет упоминание свободного времени; никакого сырого текста вида «темп задан как X» в вывод не попадает) и сохраняет в `data/programmes.json` вместе со `startDate`, скопированным из брифа.
- `GET /api/briefs` — список брифов (используется страницей `/drafts`).
- Редактор программы (`app/programme/[id]/page.tsx`): правка названия концепции, даты заезда, названий дней, полей блока (время/заголовок/описание), перестановка дней и блоков вверх/вниз, добавление/удаление дня и блока, автосохранение с debounce 800мс через `PATCH /api/programmes/{id}`, индикатор статуса сохранения. Календарная дата каждого дня не хранится отдельно — вычисляется на лету из `startDate` программы и позиции дня (`dayNumber`), поэтому при перестановке дней даты остаются привязаны к позиции, а не к содержимому.
- `/drafts` — список черновиков с ключевыми полями брифа (включая длительность/даты/интенсивность) и ссылкой на программу.

## 9. Не реализовано (относительно плана)
- Реальный AI-провайдер (GigaChat) — сейчас вместо `POST /api/programmes/generate` генерация зашита стабом прямо в `POST /api/briefs`.
- PostgreSQL + Prisma — сейчас JSON-файлы вместо БД.
- Zod-схемы для брифа и AI-ответа.
- Загрузка/замена изображений (`POST /api/assets/upload`).
- Сборка презентации (`POST /api/programmes/{id}/presentation`) и экран предпросмотра.
- Экспорт в PDF (`POST /api/programmes/{id}/export-pdf`).
- Разделение на `packages/ui`, `packages/core`, `packages/ai`, `packages/db`.
